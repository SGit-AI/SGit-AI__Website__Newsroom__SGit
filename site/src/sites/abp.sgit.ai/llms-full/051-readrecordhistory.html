read.record.history

Read a retained record: shell history, past sessions. Its effect is no: cannot be undone.

What this id is made of

This is not a string. It is read↗.record↗.host↗, three nodes joined by three edges, and each of them has an address, a page and a JSON file. Follow any of them and you get the query for that word rather than a definition of it.

NodeEdgeReads as
read↗has_verbthis capability has the verb read
record↗acts_onthis capability acts on record
host↗reachesthis capability reaches host
filesystem↗in_familythis capability is in the filesystem family
no↗has_undo_classthis capability has the undo class no

The gloss above is a convenience, not the definition. A node carries no inherent meaning: what read.record.history is emerges from the edges traceable from it. The strongest case is host↗, where the deployment shapes that use it do not agree about what it means, and the page keeps the disagreement rather than averaging it.
