read.file.host

Read any file the account can reach. Its effect is no: cannot be undone.

What this id is made of

This is not a string. It is read↗.file↗.host↗, three nodes joined by three edges, and each of them has an address, a page and a JSON file. Follow any of them and you get the query for that word rather than a definition of it.

NodeEdgeReads as
read↗has_verbthis capability has the verb read
file↗acts_onthis capability acts on file
host↗reachesthis capability reaches host
filesystem↗in_familythis capability is in the filesystem family
no↗has_undo_classthis capability has the undo class no

The gloss above is a convenience, not the definition. A node carries no inherent meaning: what read.file.host is emerges from the edges traceable from it. The strongest case is host↗, where the deployment shapes that use it do not agree about what it means, and the page keeps the disagreement rather than averaging it.

Unstated is not authorised. A mandate that never mentioned a capability did not authorise it, and the delta on every example page counts it as excess and says which kind it was.
